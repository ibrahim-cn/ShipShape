# Week 6 Requirements Traceability

Sources: `evidence/week-06/requirement-excerpts.txt` extracted from Week 2/Week 3 report PDFs. Added implementation items come from README, API design, component design, and current backend behavior; they were not numbered FR/NFR IDs in Weeks 1-5.

Test verdict and requirement status are reported separately. `PASS` in test evidence means the observed result matched the expectation; application finding values such as `WARNING`, `FAIL`, `ERROR`, and `NOT_CHECKED` are reported results, not test failures. `UNEXECUTED` and `PARTIAL` are not counted as verified.

| NFR-03 | Handle unreachable URLs, timeouts, and invalid responses gracefully without crashing | Live 401/403/404/500 produce structured results with reachable=true and HTTP Status FAIL; non-resolving domain returns HTTP 400 `Host not allowed`; deterministic timeout path passes; invalid/empty/malformed inputs return structured errors; three health checks after error batches returned HTTP 200. | Partially Verified |

### NFR-02 limitations

- No live domain deliberately resolving to a private address was available without creating an uncontrolled DNS setup; the code path is covered by deterministic resolver tests and live literal-IP rejection.
- No live public URL redirecting to an internal address was used; `WebsiteCheckServiceMoreTest.redirectToForbiddenDestination` covers redirect-target revalidation.
- The implementation revalidates resolved addresses before each request, but no separate pinned-connection-stage guard was demonstrated. DNS rebinding remains a documented limitation.
- These cases are recorded as `TC-ENV-01`, `TC-ENV-02`, and `TC-ENV-03` UNEXECUTED and `PART-NFR-02` PARTIAL in `test-case-matrix.md`.

### NFR-03 limitations

- A live connection timeout could not be forced safely because SSRF protection blocks localhost and no controlled slow public endpoint was used. Timeout behavior is verified deterministically by `connectionTimeout`.
- The service discards response bodies, so a malformed body is not separately parsed; unexpected status codes and transport failures are covered by live and automated tests.
- These cases are represented by `TC-ENV-04` UNEXECUTED and `PART-NFR-03` PARTIAL in `test-case-matrix.md`.
